# NovelAI 绘图增强版

基于 [luoxiQAQ/nekro-plugin-novelai](https://github.com/luoxiQAQ/nekro-plugin-novelai) 1.5.1 修改，保留原项目 MIT 许可证及版权声明。增强版标识：`Yasumi.novelai_enhanced`，版本 `2.0.4`，修改版作者 **Yasumi**。这是独立修改版，与原作者维护的版本区分。

2.0.4 以中性名称发布社区版，作者 Yasumi，随包提供原作者 luoxiQAQ 的预设副本，首次安装自动初始化，更新不覆盖已有预设。来源说明见 [PRESET_SOURCE.md](PRESET_SOURCE.md)。

2.0.3 新增单次额外负面提示词：`-n:内容。`。无斜杠生图回复去掉框架命令前缀，继续一条消息发送完成文字与图片；其他插件的前缀设置未改变。

2.0.2 恢复原生命令发送格式：无斜杠画图／重画也使用框架的媒体物化与命令发送通道，完成文字和图片合在同一条消息，使用原有命令输出前缀。插件管理员配置说明补充明确：在任何群和私聊中都免会话及总额度；管理员期间的生图不会追补扣额。

2.0.1 修复无斜杠画图／重画的图片发送：把插件私有目录的图片复制到当前会话上传目录，再使用 NekroAgent 可解析的 `/app/uploads/...` 路径发送。原图归档、额度和触发词配置保持原样。回归测试使用框架真实文件复制和路径解析器，聊天发送仍由测试替身接收。

新增群聊／私聊白名单、所有会话共享的每日总额度、各会话独立额度、插件管理员免额度、统一后台生图队列、429 等待重试、可配置无斜杠触发词和 `/额度`。保留原来的会话重画机制、人物／风格预设、图生图、中文翻译及画廊自动上传。

已在 NekroAgent 2.4.0、Python 3.11 的实际框架中完成隔离集成测试。普通单元测试使用 Python 3.13。需要 Python 3.11 或更高版本。

## 安装与首次配置

兼容性：已验证 NekroAgent 2.4.0、Python 3.11。需要 Python 3.11 或更高版本。

下载 Releases 中的 `novelai-enhanced-2.0.4.zip`，或克隆仓库后，把插件目录放入 NekroAgent 的持久化数据目录 `plugins/workdir/novelai_enhanced`。如果你的后台提供 Git 仓库安装入口，可填写本仓库地址；安装能力取决于 NekroAgent 的部署版本。

在 NekroAgent 的插件管理中启用「NovelAI 绘图增强版」，填写 NovelAI Token，再配置模型、翻译模型组和自定义触发词。若安装了原版 NovelAI 插件，应停用原版，避免重复响应。

插件标识固定为 `Yasumi.novelai_enhanced`，配置与数据由 NekroAgent 持久保存。安装包直接包含 `presets.json`（1062 个人物预设、61 个风格预设），首次安装会自动复制到数据目录；已有预设时保留原文件。预设来源为原作者 luoxiQAQ，详见 [PRESET_SOURCE.md](PRESET_SOURCE.md)。访问令牌、真实运行配置、用户名单和群名单不随包发布。

默认画图：

```text
/画图 示例角色，风格040
/画图 示例角色，花田，横
/重画
/重画 奔跑
/额度
```

画图和重画触发词在配置页修改。无斜杠触发词仅在消息开头匹配，可以直接连接描述，或用空格、`+` 分隔。以 `/` 开头的设置注册为斜杠指令，例如 `/绘图`、`/重绘`。这三个触发设置修改后请重载**此插件**。无需重启整套 NekroAgent。

`保留原画图和重画指令` 默认关闭，只注册配置中的画图／重画触发词（初始为 `/画图`、`/重画`）。其余原版别名如 `/nai`、`/novelai`、`/redraw` 不额外启用。其他指令沿用原版，包括 `/来点`、`/看参数` 和预设管理等。

自然语言生图保留，Agent 调用工具时也遵守白名单、黑名单、额度和队列。

## 单张图片的额外负面提示词

在画图描述中使用减号、n、冒号，并以句号结束：

```text
/画图 示例角色，风格040 -n:glasses, hat。
/画图 示例角色，风格040 -N：glasses, hat.
```

`n` 不区分大小写；冒号支持 `:`、`：`；结束句号支持 `.`、`。`。只写一段 `-n:`，可以放在描述末尾、另起一行，或放在中间，句号后的文字继续作为正向描述。权重中的 `1.5` 之类小数不会误作为结束句号。

额外负面词追加到插件默认／配置的全局负面提示词中，不会覆盖默认值，也不会改变后台设置。缺少结束句号会提示语法错误，不会提交生图或扣额度。英文标签可以直接使用；中文额外词会使用现有翻译模型处理，未配置翻译模型时建议使用英文。

重画仍使用原会话上一张图片的参数，并默认沿用其额外负面词。重新写 `-n:` 时替换额外部分，例如：

```text
/重画 -n:glasses。
```

清空上一张的额外负面词，但保留全局默认值：

```text
/重画 -n:。
```

以上触发词是初始默认示例，使用时替换为你在配置页设置的画图／重画触发词。Agent 工具原有的 `negative_prompt` 参数继续支持额外词，提示词中直接带 `-n:` 也能解析。

## 白名单与管理员

群聊白名单、私聊白名单分别有独立开关。开启后，只有列出的群或用户可以生图；开启但列表为空表示全部禁止。

每行一个群号／平台用户号，可附备注，也可填完整 `chat_key`。白名单群中所有成员共用群额度，不设置个人每日上限；黑名单中的用户仍被拒绝。原黑名单格式和其他管理指令保留。

`插件管理员` 每行一个平台用户号。这与 NekroAgent 管理员身份无关。插件管理员在任何群和私聊中都免除所有每日额度，也不占用总额度，即使指定群额度或私聊默认额度设为 1 也不会限制这些用户。仍受白名单、黑名单和后台排队约束。需要测试普通用户限制时，使用未列入插件管理员的用户；从管理员列表移除后新增生图才计额度，之前免额的记录不追补。额度设置只能在后台修改，没有聊天中的额度分配指令。

## 每日额度

**新安装时，白名单和每日限额开关默认关闭。** 请先填写名单及额度，再按需要启用。

初始展示值：总额度 100，群默认 20，私聊默认 5。开关关闭时这些数字不限制现有使用。`0` 表示禁止普通用户生图，`-1` 表示不限。

所有群聊和私聊共享总额度，此外每个会话受自己的每日限额约束。没有群内个人每日额度。

后台可单独分配，例如“指定群聊每日额度”：

```text
123456=50
234567=10
```

“指定私聊每日额度”格式相同。支持完整会话键，示例：

```text
onebot_v11-机器人号:group_123456=50
```

北京时间每日 00:00 切换日期。任务入队时预占额度，成功生成并在本地保存后正式扣除一次；确定失败或结果不确定时返还。正在执行的任务计入开始执行当天；跨零点仍在等待的任务开始前重新预占新一天额度。`/额度` 显示总额度与当前会话剩余值，包含预占。

成功保存后，图片发送失败或画廊上传失败不会再次生成，也不重复扣额度。插件额度返还并不代表 NovelAI 服务商返还 Anlas。

## 后台队列和重试

画图、重画、换人物和 Agent 文生图／图生图都使用同一个 FIFO 队列，一次只执行一个生图任务。顺序按通过验证并入队的顺序确定，先入队再翻译。

每个用户同时最多一个未完成任务，这是防刷保护，与个人每日额度不同。总未完成任务数默认 20，可在配置页调整，管理员也遵守排队。

有效请求入队后立即回复 `生成中的回复文本`，默认是原版的“🎨 正在绘制中，请稍候...”。此文本可自定义或留空。不会显示队列位置，也不会再发送一次“开始生图”。

429 在后台等待后重试，默认每次至少 15 秒、最多重试 3 次（加上首次请求共 4 次）。收到更长 `Retry-After` 会延长等待，单次最多 600 秒。重试保留同一份提示词、参数和种子，不切换 Token。只有达到上限仍失败才告知用户。

401／402 保留有限的 Token 轮换；请求失败文本不会回显远端响应中的密钥或代理地址。网络超时可能意味着远端已经生成，属于结果不确定，不自动重画且不扣插件额度。

额度和任务去重记录存入 SQLite。停用／重载时，未完成任务中断并返还额度。异常退出后保留任务记录并标记中断，**不会自动重新生图**；需要用户发送新指令。不同部署之间各自计算额度和排队。

## 画廊上传

配置画廊接口地址与上传密钥后，PNG 原图与生成参数通过持久上传队列归档。上传与下一张生图分开运行；失败时自动重试，画廊可根据原图哈希去重。

新安装的默认画廊地址为空，需自行设置。人物／风格预设已随安装包提供，不包含原部署的私人配置。

## 在另一台机器安装

1. 下载版本 ZIP，解压后把 `novelai_enhanced` 文件夹放入那台 NekroAgent 的**持久化数据目录**下 `plugins/workdir/`。Windows 官方启动器的部署同样要放到其 WSL 内的数据目录，而不是只解压到 Windows 桌面。
2. 若框架没有所需依赖，在 NekroAgent 自己的 Python 环境安装 `httpx`、`Pillow`、`PyYAML`，不要安装到宿主机上无关的 Python 环境。
3. 在插件管理加载／重载 `novelai_enhanced` 并启用。必要时按那台部署的官方方式重启以发现本地插件。
4. 填写该机器的 NovelAI Token、模型、翻译模型组、白名单、额度及插件管理员。随包人物和风格预设已自动初始化，也可导入自己的预设。
5. 若要上传到同一个画廊，再配置画廊上传地址和上传密钥。确保那台机器可以访问该画廊。
6. 停用原 NovelAI 插件，避免重复响应。

ZIP 和 Git 仓库不包含 Token、真实配置、图片、群／用户名单或额度数据库。GitHub 发布不等于已上架 NekroAgent 社区。

## 云端连接 NovelAI

云端运行环境能够直接访问 `https://image.novelai.net` 时，`HTTP_PROXY` 与 `API_PROXY` 可以留空。

- `HTTP_PROXY`：填写该运行环境能够访问的 HTTP 代理，例如 `http://proxy-host:7890`。SOCKS5 需要在运行环境安装 `httpx[socks]`。
- `API_PROXY`：填写可信反代的基础地址，不包含 `/ai/generate-image`；插件会自动追加 `/ai/` 与对应接口路径。
- 在 Docker 中，`127.0.0.1` 指向插件容器自身；宿主机上的代理需使用容器可访问的地址。

只迁移源码不会迁移本机代理配置。接入同一画廊时，在云端重新填写画廊地址和上传密钥。
